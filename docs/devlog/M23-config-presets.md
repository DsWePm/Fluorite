# M23：TOML 配置预设导入与导出

M23 于 2026-08-14 完成功能验收。它把 Fluorite 约 300 项分散在同一注册表中的设置整理为可移植、版本化、可事务替换的 TOML 预设，并明确区分可即时应用的设置与必须等待重启的资源设置。当前长期架构、风险和待办仍以 [`docs/DEVELOPMENT.md`](../DEVELOPMENT.md) 为准；本文保存 D156–D159 的产品裁决、实现方法、失败修复与验收记录。

## D156A：完整可移植预设

- 预设导出全部质量、性能与功能设置，不提供分类导出；缺失键在导入时使用该格式版本的代码默认值，因此语义是完整替换，不是 merge。
- `ngx.path`、`diagnostics.*`、frame stats、灯光/OMM dump 和实体 capture parity 等机器本地或诊断状态不进入预设。活动配置被替换时保留旧文件中的这些值，不能把 `-Dfluorite.*` 提供的路径泄漏进共享预设。
- 导出通常读取当前有效运行值；已经选择但等待重启的配置值优先于旧运行值。系统属性仍代表实际最高优先级，因此导出时继续以当前系统属性覆盖后的值为准。

## D157A：设置页与文件交互

- Fluorite 设置中心底部依次放置横跨两栏的“导出预设”“导入预设”“恢复默认值”。导出与导入文字为粗斜体；恢复默认文字为红色粗体，并使用确认页防止误触。
- 导入/导出使用 Minecraft 已携带的 LWJGL tinyfiledialogs 原生文件选择器，不新增平台依赖。默认目录是 `config/fluorite-presets/`，默认名为 `fluorite-preset-yyyyMMdd-HHmmss.toml`。
- 导出禁止覆盖活动 `fluorite.toml`；取消文件窗口不产生错误页。成功页报告实际 LIVE 变化、待重启变化、活动系统属性覆盖数量和备份位置。
- 只维护 `en_us` 与 `zh_cn`，其他语言回退英文。

## D158A：严格 schema 与事务替换

format 1 的根结构固定为：

```toml
[preset]
format-version = 1
scope = "portable-full"
created-at = "2026-08-14T00:00:00Z"

[settings]
# 完整嵌套设置
```

- 根表、元数据键和 scope 必须精确匹配。未知键、非可移植键、错误类型、越界整数/浮点、NaN/Inf、未知枚举和版本不符会拒绝整份文件。
- 解析、展平、默认填充和所有设置验证先在内存完成；成功前不改变活动文件或运行设置。
- 活动配置先构造到同目录临时文件，再把旧文件原子保存为 `fluorite.toml.bak`，最后以原子 rename 发布新文件。文件系统不能保证原子替换时失败，不降级为有覆盖空窗的写法。
- 未来旧格式只能通过显式迁移器进入；不能把未知版本按当前 schema 猜测读取。

## D159B：LIVE / RESTART 两层应用

- 策略默认 `RESTART`。只有已经由逐帧设置 UI 和资源生命周期证明安全的 allow-list 才是 `LIVE`，因此以后新增设置不会意外热应用。
- 雾、天空、天气、维度玩家修正、水（`water.deform-mode` 除外）、曝光、后处理、HDR 亮度标定，以及公开的 tracing、BSDF、粒子和 DLSS-RR 质量项可即时应用。
- `hdr.enabled`、`water.deform-mode`、worker、terrain、OMM、容量、FG 和 Reflex 等保持待重启。只有与当前配置确实不同的值计入成功页数字。
- 待重启值只写入活动 TOML 和 pending map，不修改本进程资源。普通 `save()` 先写运行值，再以 pending 值覆盖同一路径，防止在退出设置页时把导入选择写回旧值。用户随后明确修改同一项会清除它的 pending。
- 活动 `-Dfluorite.*` 继续拥有最高优先级：导入值保存在文件下层，本进程不覆盖系统属性，并在结果页单独报告。

## 浮点边界失败与修复

首轮验收时，当前配置中的 `weather.puddle-roughness = 0.002` 能导出，却被同一版本导入器判为低于下限。根因不是 UI 范围不同，而是严格校验比较了两个不同数值域：

- TOML parser 读取十进制 double `0.002`。
- 注册表下限是 float `0.002f`，提升为 double 后等于约 `0.002000000094…`。
- 旧代码在 double 域做精确 clamp 比较，因此合法的 `Float.toString()` 输出无法通过自己的边界。

最终校验先把外部值变换到设置真正存储的 float 域，再判断 clamp 是否改变该 float，最后转回 TOML 外部域。这样精确下限 `0.002` 能往返，真实越界 `0.0019` 仍被拒绝；没有用任意 epsilon 放松所有范围。该失败先以真实导出→导入回归测试复现，再修复为通过。

## 验收与验证

游戏内验收通过以下行为：三个底部全宽按钮及样式、恢复默认确认页、原生导入/导出窗口、当前配置直接往返、即时设置应用、待重启提示和失败原子性。

自动验证覆盖：

- 所有可移植设置完整导出和严格回读；机器本地项不出现。
- 缺失设置回默认；未知键、类型、范围、有限值、版本和枚举整单拒绝。
- 角度等外部域变换不重复应用。
- float 精确下限可往返，明确低于下限仍拒绝。
- 活动配置原子替换与 `.bak`。
- 待重启值在普通保存中保持优先，LIVE/RESTART 关键边界固定。
- Fabric 全套 JUnit、Fabric/NeoForge 完整构建、common loader-agnostic 扫描、中英文 JSON 解析和 `git diff --check`。
