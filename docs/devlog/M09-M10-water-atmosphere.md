# M09–M10：水体介质与 LUT 大气

本日志保存水体散射从错误参数化走到 σa/σs 物理系数，以及大气从重复的 CPU/GPU 解析实现收口到 LUT 链的过程。

## M9 最终成果

水不再使用一个“浑浊度”同时承担颜色和浓度。最终参数语言是：

- 吸收 `σa` 与散射 `σs` 是独立创作量。
- 手动吸收与散射都拆成“平均强度 × mean-normalized RGB shape”，颜色不再偷偷改变平均系数。
- `σt = σa + σs`，single-scattering albedo 由 `σs/σt` 得到并受能量域约束。
- 均质水段使用闭式 Beer transmittance 与闭式 view-path 权重。
- 太阳项使用按光学深度分层、段内逐像素逐帧 jitter 的阴影线；水下方向经过 Snell 折射。
- 多次散射采用 `g_eff = g^(1/(1-ω))` 与扩散衰减近似。
- 天空项读取共享天空 Radiance，并由上射线水深和局部开放度门控。
- 焦散保留本项目的解析雅可比路线，RGB 使用不同 IOR 表达色散。

M17 后，默认散射顶点估计器取代了 M9 分层视线估计器；M9 的参数与能量契约仍然有效。

## 与 HPWater 的最终分歧

| 议题 | HPWater 的方法 | Fluorite 的结果 |
| --- | --- | --- |
| 参数 | absorption/scatter 两组颜色 | 只采纳“二者独立”的思想；重新定义为强度和光谱形状，常数自行推导 |
| 积分 | 光栅管线中的多步 ray march | 均质路径用闭式积分，只有光源可见性采样 |
| 多次散射 | 高反照率时向各向同性相位插值 | 使用 `g_eff` 与扩散衰减，避免照抄漏 `1/(4π)` 的相位约定 |
| 环境光 | 烘焙间接光乘强度 | 共享 `mediumSkyRadiance`、水深和局部天空开放度 |
| 焦散 | 光子抛撒、级联图集、去噪 | 解析雅可比；不需要图集、时域去噪，天然进入反射和折射 |
| 交互波 | 2D 波动方程与光栅障碍图 | 方程思想保留；实际障碍最后由 CPU 查询 level，见 M12 日志 |

HPWater 的数值常数没有被带入项目。其相位函数缺失 `1/(4π)`，参数已围绕能量错误调过；照抄会制造约 12.566× 的能量偏差。

## 七轮水体诊断

### 三次参数化弯路

1. 单一“浑浊度”只增加 `σs`，数学上必然让 albedo 趋近 1；越浑只能越白，不能越暗。
2. 为了让 albedo “可推导”而令 `σs ∝ σa`，会把比例变成灰色反照率；深水极限中每个群系都趋向同样的乳白。
3. 继续增加深度衰减无法修复错误光谱参数化，观察自然不变。

这段经验确立了一个原则：不能为了非目标属性的形式整洁，牺牲真正需要保留的颜色自由度。

### y≈48 亮度跳变

先后被否决的解释包括第一人称身体、TAA jitter、曝光双峰、深度分支、全屏共用阴影线，以及 `waterAnchor.w`/Snell 光程。最后一项确实包含真实缺陷，但修复后现象仍在，因此不能称根因。

真正的根因由 `water.scatter-source` 四档和 `water.sun-shadow` 的判据表测出：固定光学深度的二值太阳阴影样本没有时域去相关，遮挡边界会让整屏样本一起翻转。处置是给每层样本加入逐像素逐帧 jitter，并在后续 M17 把局部天空可见性移到真实散射点。

这次调查形成 F12：代码里发现的真缺陷和用户看到的现象是两个集合，只有隔离实验能证明交集。

### 相机前缀能量所有权

后续回归再次证明，同一个水段的 in-scatter 和 transmittance 不能拆给两个 pass。Pass A 提前乘 Beer、Pass B 为避免双计而使用零消光介质，会保住吸收却删除散射；配置和系数日志仍正常，因此症状容易被误判为热更新失效。最终契约是 Pass A 只解析边界，Pass B 一次消费完整 `SegmentIntegral`。

## 水体性能基线

Minecraft 相机是一个点，不存在“半潜机位”。因此建立了两个不同世界：

- `bench-water-bottom`：完全潜水，测封闭水介质主路径。
- `bench-water-top`：贴水面上方，测空气雾与水面混合路径；该机位尚未完成正式采集。

2026-08-05 的同批次数据：

| 路径 | `gpu.traceIndirect` 结果 |
| --- | --- |
| M9 分层水散射 | 10.49 ms，占当时帧约 25% |
| M17 散射顶点 | 7.56 ms，占当时帧约 19% |
| 旧 `bench` 世界 | 同期约 21 ms |
| `bench-water-bottom` | 同期约 42 ms |

这证明没有大水体的 `bench` 世界无法回答水体性能问题。

## M10：LUT 大气

M10 将大气收口为 GPU LUT 链：

1. M10.1：删除 CPU 版 `atmosphereTransmittance`，建立 256×64 transmittance LUT。
2. M10.2：增加 32×32 multi-scatter LUT。
3. M10.3：增加三张 192×128 sky-view LUT；相位函数保留在读取侧，因为 Mie 前向尖峰窄于 LUT 方位轴分辨率。
4. M10.4：增加 64×36×64 aerial-perspective froxel。

`RtSky.recordSkyViewBake` 持有链条顺序和 barrier：transmittance → multi-scatter → sky-view → medium-sky reduction → froxel。CPU 只上传未染色的天体峰值，所有消费者在 GPU 侧通过同一大气模型染色。

M16 后，完整 sky-view 上半球按立体角 reduction 为 `mediumSkyRadiance = 1/(4π)∫Lsky dω`，水、marched fog 与 froxel 共享这个源。M16 的有限面积太阳地平线连续性、能量口径和后续验收详见 M15–M17 日志。

## 仍然有效的风险

- 色散的物理 1× 在 RGB IOR 下几乎不可见；当前默认是有意夸张的创作值，不得称为物理强度。
- `CAUSTIC_MAX` 可能夹平色散，尚未定案。
- `bench-water-top` 仍是测量欠账。
- 间歇性水面消失与水下曝光闪烁不属于本里程碑的已结案问题，当前统一记录在 GitHub Issue #20。
