# M12–M12.5：水体仿真与真形变

M12 建立局部交互波场，M12.5 让同一波场真正移动水面几何并重做程序波谱。本日志保留方案裁决、设备故障和最终结构；当前操作规则见主文档。

## M12：交互水体仿真

### D39–D42

| 决策 | 结果 | 物理与性能取舍 |
| --- | --- | --- |
| D39 网格 | 256²，高度场 R16F×3，默认覆盖 64 blocks | 固定网格下，范围越大格距越粗；512² 会把光线和显存都放大 4 倍 |
| D40 障碍更新 | 只在域移动或地形改变时更新 | 稳态接近零成本；地形变化到掩码更新允许一帧延迟 |
| D41 与海浪结合 | 斜率相加，局部仿真在域边淡出 | 波谱和涟漪不相互作用，不是完整流体；换来域内外仍是一片连续海面 |
| D42 冲量 | 实体、方块变化、抛射物/浮漂；雨不注入高度场 | 大量雨滴会把网格变成高频噪声，降雨改由全局 ripple 表达 |

`water_sim.comp.slang` 使用显式蛙跳线性波方程。蛙跳必须同时读取两个历史态，因此使用三缓冲轮换；障碍边界使用 Neumann 反射；外圈海绵层吸收离开域的波，避免整个域成为反射浴缸。冲量写入 next 态并使用平滑 bump，避免单格 delta 把 Nyquist 棋盘格永久留在场里。

CFL 条件 `c·dt/dx < 1/sqrt(2)` 在 CPU 侧钳制。水面采样统一进入 `applyWaterWaves`/其时域配对接口，使主光线、RR guides 和焦散读取同一场。

### 障碍判据返工

第一版每格向下发 TLAS 短光线，但水面本身就是 section BLAS 的几何；探测首先命中水面，导致每格都被判障碍。给水单独 cull mask 也不可行，因为 mask 是逐实例的，而同一 section 实例同时包含石头和水。

最终采用 CPU 查询 level：在重锚/脏区更新时检查水面下方 `FluidState`，生成 256² 障碍掩码后上传。它直接回答“这里能不能传播水波”，比在共享 BLAS 中绕过水几何更简单且准确。

## M12.5：水面真形变

法线扰动不会移动轮廓。光栅参考项目可以在 vertex shader 免费位移，光追管线则必须更新顶点并 refit BLAS；这是同一视觉思路在不同架构中的成本分野。

### D44–D49

| 决策 | 结果 |
| --- | --- |
| D44 方案 | 近处水面顶点位移 + 每帧 BLAS refit，远处继续纯法线。intersection shader 路线因双水面表示和介质边界风险被否决。 |
| D45 距离 | 形变距离独立；仿真域范围被形变范围钳住，不能仿真几何无法表达的涟漪。 |
| D46 一致性 | 网格只表达其 Nyquist 内的低频形状，着色法线始终由完整解析场重建；网格和法线不是两套波。 |
| D47 开关 | 关闭形变必须逐位回到纯法线行为；形变域使用整纹素锚定。 |
| D48 交付顺序 | 先对原有水面顶点原位 refit，再考虑细分；实测 1 m 网格已经能表达程序波谱约 97% 的高度。 |
| D49 振幅 | 高度和坡度由同一个总振幅一起缩放；默认 1 保持发布行为。 |

波场被移到无 binding 的 `water_wave.slang`，compute 和 ray stage 通过参数读取同一数学。`WITH_HEIGHT` 分支同时给出高度和梯度。

首次让几何读取高度时暴露了一个法线无法看见的偏置：尖峰剖面 `exp(S(sinφ-1))` 恒正，直接求和让水面整体抬高约 27.8 mm。最终每个分量减去解析均值 `exp(-S)I0(S)`，且均值随 LOD 权重一起淡出；CPU 有限差分与解析梯度的相对残差约 `5e-5`。

## 形变构建与设备故障

### 第一次：构建输入双重所有权

开启形变后 TLAS 读取已释放 BLAS backing，Vulkan device fault 只给出 `READ_INVALID` 和上一个资源名，没有 Java 栈。根因是：

- 已发布的 `SectionGeom` 需要长期保留 positions/indices 供 refit。
- 未发布或作废的 `PreparedSection` 又必须在 destroy 时释放这些输入。
- 原实现从状态推断所有权，两个路径都可能释放。

修复使用共享的 `inputsTransferred` 原子标记，在发布前显式转移所有权。这个故障确立：异步资源所有权必须记录，不能从“通常走哪条路径”推断。

### 第二次：AS flags 三处不一致

尺寸查询和结构创建使用 `buildFlags(allowUpdate)`，构建录制却写死 `buildFlags(false)`。scratch 按一组 flags 分配，命令按另一组执行，驱动可越界而验证层不一定报告。

长期规则：加速结构 flags 在尺寸查询、结构创建、构建录制三个位置必须逐位一致。审计时 grep 构造 flags 的函数，不只 grep 新 flag 名。

### F24：可更新 BLAS 不压缩

Vulkan 规范没有说明压缩拷贝产物是否继承 `ALLOW_UPDATE` 构建属性，现有验证层也不追踪这条状态。错误会表现为静默几何损坏，因此本项目采用保守契约：需要 refit 的 BLAS 不做 compaction。

## D55：路 3′ 消除重锚闪烁

问题来自把两个概念绑在一起：“构建时允许形变”和“本帧实际参与形变”。near 模式跨边界会改变 section 的构建模式，必然触发一圈重建和可见闪烁。

最终 `water.deform-mode=all` 让所有含水 section 在构建时保留可更新资源，但每帧 dispatch/refit 仍按距离剔除。这样没有构建边界可跨，每帧工作量仍由可见范围限制。

代价是固定内存而非每帧时间：含水 section 常驻 positions、indices 和静止副本，并放弃 BLAS 压缩。`near` 保留给内存紧张机器，但它保留重锚闪烁风险。形变打开需要重载世界；关闭只停止派发，可即时生效。

## D50、D57 与 D72：波长、速度和天气

- `water.wave-length` 控制最长波长，十个频带按 1.5 比例缩短。
- 深水色散 `ω=sqrt(gk)` 绑定波长与相速度；不提供逐波长独立速度旋钮。
- `water.wave-speed` 是所有频带共同的全局时间倍率，保持频带之间的相对色散关系。
- 冲量半径使用世界单位；网格无法表达小时，扩大半径并按面积比降低振幅，以保持移动水量。
- D72 禁止天气实时改写已累计绝对相位使用的 `k/ω`。十个波长和相位固定，20 秒内只把权重从部分短波转向已有长波，因此天气切换不再移动当前浪峰。

## D56：FFT 不实施

当时程序波谱约占 trace 的 7.5%（约 0.90 ms/12 ms）。FFT 的价值不是这十个分量更便宜，而是固定成本可以容纳上千分量；用户真实诉求“去掉规则网格感”最终由交叉波系、全频段 meander、整数哈希、域扭曲和阵风斑块解决。

FFT 被否决的理由：

- 新增完整频谱/纹理/时域子系统。
- 4096 锚定周期引入可见 tile 风险。
- 丢失当前解析时间导数。
- 高斯海面会削弱项目现有尖峰宽谷的风格。

设计仍保留作未来重新评估的历史，不是当前待办。

## F22–F28：波场诊断经验

- F22：所谓“唯一入口”若调用方仍能自己拼等价逻辑，就不是不变量。主光线时域法线曾绕过仿真；修复后内部 API 迫使所有消费者走同一入口。
- F23：debug view 23 直接按屏幕 UV 展示高度场，只证明场存在，不能证明世界→域映射。view 24 用真实水面命中点走着色采样，二者必须分开。
- F25：平行四边形波纹不是网格、域扭曲或波长有理比，而是最后三个短波没有 meander。分量范围滑条一次隔离命中。
- F26：注释“只有长波需要 meander”从一开始就把结论写反；说明“不做某事”的注释最容易保护错误。
- F27：`frac(sin(dot()))` 哈希在 40×40 格只产生约 660 个不同值，并随大坐标退化；改为整数哈希后 1600/1600 唯一。项目中这类 sin hash 应视为待审计。
- F28：域扭曲只影响与自身尺度相近的结构。`A/L` 过大时雅可比翻转并产生折痕；当前钳到 0.25，低于实测折叠阈值。

## 验收与未结债务

M12/M12.5 已通过功能与视觉验收。小水场景曾测约 4 个 section、`gpu.waterDeform≈0.27 ms`，但海洋场景的 refit、显存和 all 模式常驻成本仍未正式采集。

间歇性“水面消失 + 水下闪曝光”没有稳定复现，且现场 `gpu.waterDeform=0`，不能归因于形变。后续只在 GitHub Issue #20 记录证据；诊断在根因确认前保留。
