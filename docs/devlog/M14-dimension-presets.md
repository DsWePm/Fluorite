# M14：维度预设与地狱介质

M14 把维度差异从散落的维度判断整理为版本化 Provider/preset，并完成第一个非大气 Provider：地狱本地光与均匀雾。主世界保持既有物理大气；同一分支随后把末地 HDRI/Kerr 黑洞推进到待游戏内验收状态。

## 架构与资源所有权

`RtSkyPreset` 从 `assets/fluorite/fluorite/sky/<namespace>/<dimension>.json` 加载。资源包可覆盖内置 preset；加载器校验 format、有限值、范围和介质能量关系，并逐文件隔离错误。未知、缺失或无效的模组维度回退到完整物理大气，不根据 `dimensionType()` 猜环境。

参数顺序固定为：preset 基础值 → preset 允许的时间/天气 forcing → 用户全局修正 → 玩家逐维度修正。shader 只读取 `SkyProvider` 与能力标志，不接触维度 ID。`skyProvider/environmentFlags` 使用 `WorldPush` 既有 8 B padding，结构仍为 944 B。

大气 Provider 继续运行 transmittance、multi-scatter、sky-view、reduction 与 froxel 链。非大气 Provider 跳过无意义的大气 bake；资源包若给非大气维度启用云或结构雾，当前仍会为共享静态纹理生命周期执行一次 bake，只有实测加载成本值得时再拆。

## 地狱 Provider

地狱关闭太阳、月亮、Rayleigh/Mie/臭氧、程序星空、云和天气 forcing。本地熔岩、萤石等发光体使用 RT 与 froxel 共用的 `light_sampling.slang` Light/alias/grid 接口；froxel 每个样本做一次局部发光体 NEE 和阴影线，没有复制第二套光源格式。

环境介质是关闭噪声的均匀白雾。另有 D78A 批准的极低中性白可读性保底光：它不受遮挡，只进入漫反射、逃逸背景与介质环境源，不伪造镜面环境。这个近似明确服务于可读性，不宣称物理准确。

“维度设置”只控制精确的 `minecraft:the_nether`：

- 地狱雾开关；全局体积雾仍是总开关。
- 地狱雾浓度倍率 `0–2`，默认 `1`；它与全局雾倍率合并后的最终玩家增益仍夹在 2。
- 地狱环境光倍率 `0–8`，默认 `1`；统一缩放保底光、逃逸背景和雾/水环境源，不改变局部发光体功率。
- 末地只保留人类可见的空分组，不发布无效旋钮。

## DLSS-RR 浓雾边界

视觉验收发现：地狱雾倍率很高时，DLSS Ray Reconstruction 会把远处白色表面重建成绿色；靠近后恢复。把环境光提高到 `8×` 不改变绿色，降低雾浓度则立即恢复，因而排除了“中性环境基线过低”。这确认了高密度远景体积与当前 RR 路径的行为边界，但没有进一步声称问题位于 RR 模型本身还是其低覆盖率 guide 输入。

产品裁决是把逐维度地狱雾倍率限制为 `0–2`，并把全局与地狱倍率合并后的最终玩家增益夹在 2。限制同时存在于配置值域、UI 和最终参数解析：旧 TOML、系统属性或运行时写入超过 2 都会被夹到 2，界面也不会显示无法生效的更高值，全局倍率也不能从旁路重新越过边界。这是当前 RR 兼容性边界，不是物理介质的理论上限；升级 RR/驱动或重做 guide 后可用同一远近白色表面用例重新评估。

## 验收与验证

游戏内确认了地狱不残留地球大气、天体、云或天气响应；均匀雾可被本地发光体染色并正确受遮挡；逐维度雾和环境光控制不泄漏到主世界。高密度远景绿色通过 `0–2` 上限隔离。

代码侧通过：

- 全量 Slang shader 编译。
- preset 加载/回退、WorldPush ABI 与逐维度控制测试。
- Fabric 和 NeoForge 完整测试与构建。

## 末地路线状态

末地实现已进入同一 M14 分支，但尚未取得游戏内视觉与性能验收，因此完整当前合同仍保留在主文档待办。实现使用 Space Spheremaps 的 CC BY 4.0 `HDR Multi Nebulae 1`、Cartesian Kerr-Schild transfer 和运行时有限厚度 disk `Le/T`；可见结果仍按 `Ldisk + Tdisk·background` 合成，并让可见盘与有限面积天体 NEE 调用同一个运行时求值器。D87C 决定 10K 母版不进入 Git/LFS，构建通过固定 URL、SHA-256 和可选本地覆盖取得精确字节。旧“项目自有 CC0 星空、Boyer–Lindquist transfer、光学厚类别盘”路线已废止，不得恢复。

D91A 证明末地没有烘焙或叠加主世界程序星星；低清来自 10K→4K 缩放、质量 3 的 533×300 内部追踪和直接视线约 mip 1.4 的组合。实现只给直接相机环境 miss `-1 mip` 重建偏置；payload bit 3 在 miss 输入阶段表示 direct-view，在 hit 输出阶段仍表示 dielectric-entering，命中 shader 完整重写 flags，因此不扩张 payload，也不污染反射、折射、间接或 debug 射线。

D92A-1 没有替换 Kerr 几何，也没有复制无许可证参考仓库。它独立重做静态 disk 源模型：保留 NT 径向次序、Kerr `g⁴`、同一 `Le/T` 可见/NEE 契约；用随半径剪切的 broad/detail/fine 三层噪声形成不规则流动尘带，以结构同时驱动盘厚、消光和源函数，并把旧 6× 白色 shoulder 改为有界暖色可见光代理。第一版显式六臂在离线预览中形成规则花瓣，已在进入游戏前淘汰。最终生成结果为 16,475 个盘影响 texel、最大基准 `Le≈0.92`、左右积分能量比约 4.37；不含 bloom。该路线的盘结构被烘焙固定，随后被 D93A-R 取代，仅作为失败路线和参数演进记录保留。

D93A-R 根据用户要求把盘改成动态，但保留已验证的 Kerr 几何。离线生成器不再输出静态 `rgb=Le, a=T`，而是为每个方向记录最大设计盘体积内第一段连续 Kerr chord：entry 图为 `xyz + energy`，exit 图为 `xyz + angular momentum`。本次 2048×1024 冷生成耗时 8 分 32 秒，得到 2,093,525 条 escape、3,627 条 capture、19,169 条有效 chord，最大长度 6.99M；测试确认全部有效 chord 位于 D85 的 `0.36 rad` proposal 内。

运行时沿 chord 固定取 12 个样本，以独立编写的五层 value noise、径向剪切、NT 径向次序和 Kerr `g⁴` 求有界 `Le/T`。直接可见、BSDF 路径和盘面 NEE 共享这一个求值器，避免“看见的盘”和“照亮世界的盘”参数分叉。该实现只从 [rossning92/Blackhole](https://github.com/rossning92/Blackhole) 借鉴公开的思路、公式和参数比例；因上游没有许可证，本项目没有复制其源码、shader、噪声实现或资产。它是面向动态观感的可见光近似，不宣称严格天体光谱准确，也没有加入参考项目的 bloom。

D96A/D97A 把视觉构图控制拆开：盘外半径 `4–12M`、默认 `8M`；盘厚度为独立设计的 `0.55M` 基准半厚度之 `0.25–2×`、默认 `1×`；HDRI 绕实际 Kerr 自旋轴以连续游戏时间旋转，范围 `0–1°/s`、默认 `0.02°/s`。星空亮度、盘亮度、外径、厚度和旋转速度互不补偿；旋转只作用于逃逸方向后的 HDRI，黑洞与盘固定。上述实现已通过生成器、KTX、shader、Fabric 和 NeoForge 自动验证，等待游戏内动态观感与性能验收。

用户随后判断当前实时吸积盘在美术表现上仍不适合继续调参，决定暂停该路线：D93A-R、D96A、D97A 的代码与自动验证结果暂时保留在未提交分支，但不作为最终 M14 方案，也不在此时提交 PR。后续由用户在 Blender 中预渲染包含星空背景、引力透镜黑洞和动态吸积盘的可循环 HDR 全天球序列，素材完成后再恢复集成。

已确认动态序列可以接入，且最终必须提供独立的环境亮度与对比度控制。亮度按线性辐亮度倍率实现；对比度推荐在 log-luminance 域围绕 pivot 处理并保持 RGB chromaticity，而不是在 raw RGB 或显示映射后做可能产生负值、裁剪和色偏的线性对比度。它们必须同时作用于可见环境和照明估计。若用户只输出合成 HDRI，星空与黑洞/盘无法再可靠分开调节；要保留独立参数需额外 layer 或 mask。

素材交付时再裁决：逐帧格式、分辨率、帧率、循环长度、时间映射、是否插帧、磁盘/VRAM 预算，以及环境照明使用逐帧重要性分布还是有限面积代理光。纹理数组最直接但容量随帧数线性增长；双帧流式上传节省 VRAM但增加资源调度；HDR 视频节省磁盘但引入解码、平台兼容和随机访问复杂度。逐帧环境重要性采样最接近画面真实能量但数据和更新成本更高；代理光接近现有性能但只能近似动画中的发光区域。未取得用户选择前不得实现其中任何一种。
