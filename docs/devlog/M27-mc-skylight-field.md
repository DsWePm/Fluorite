# M27：MC 天光场（已尝试，合并前放弃）

把 Minecraft 已经算好的天光做成 384³ 的 R8 环形场送上 GPU，给可见性网格够不着的远雾当数据源，同时替换 `volumeSkyOpenness` 里 +Y 出格返回 1.0 的常量（#73）。**代码完成、契约测试全过、游戏内复验未做时被用户裁定放弃**（2026-09-02）；分支 `feat/mc-skylight-field` 保留作证据，PR #75 已关闭。

## 做了什么

- CPU 侧 `RtSkyLightField`：环形寻址、每帧 96 section 预算、mapped 上传缓冲；`RtSky` 的 `R8_UNORM` 384³ 图与上传；帧统计计数器。
- 雾的远段改读该场，带「远处雾天光响应曲线」；`volumeSkyOpenness` 的 +Y 出界从常量 1.0 改为读同一个场（#73 的目标）；关档全部等价旧常量（铁律 8）。
- 体积调试视图补了不依赖几何的采样探针（「调试采样距离」），marched 雾的两个光源（天空项/太阳项）可以分开隔离，新增 debug view 29（MC 天光场）与 30（雾实际用的开阔度）。
- 契约测试 `RtSkyLightFogContractTest` 8 条，其中一条扫描所有 `import volume_visibility` 的 shader 必须同时 import `sky_light_field`（binding 30 随 module 传染）。`:fabric:test` 236 项全过。

完整组成见 [PR #75](https://github.com/DsWePm/Fluorite/pull/75) 的描述（已关闭，正文仍可读）。

## 为什么放弃

两个层面的原因，按时间顺序：

1. **机制层面的已知局限**（落地时已记录）：MC 天光是**洪水填充不是天空可见度**——开口竖直列一路 15 不衰减（60 格深天坑底读满开），横向每格才掉 1（拐进侧洞 5 格还有 67%）。它算的不是网格那个余弦加权上半球积分，同一个点两者可差一个数量级，且在深洞与侧洞里**系统性偏亮**，偏的方向和 #41 原症状相同。它只被允许用在网格无话可说的地方。
2. **路线层面的替代**（用户 2026-09-02 裁决）：雾气部分需要结构性重构（→ M28）。M28 的方向性天空场（可见性网格每格跨帧累积**带真阴影线的天空方向样本**）在「天空可见度」这个物理量上是对的，不继承洪水填充的偏差；数据源因此不再需要 MC 天光，这套基础设施整体作废。
