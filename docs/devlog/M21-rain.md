# M21：雨天表面系统

M21 在 2026-08-14 完成功能视觉验收。它把降雨从固定亮度的光栅装饰扩展为世界锚定、可遮挡、具有连续湿润历史并与路径追踪材质和统一光源接口相连的系统。长期架构、ABI 和回归标准仍以 [`docs/DEVELOPMENT.md`](../DEVELOPMENT.md) 为准；本文保留 D105–D129 的结案摘要。

## 最终成果

- 沿全局雨向维护 256²/512² 世界空间暴露深度图，以 32² tile 近场优先、远场渐进更新；每帧最多 8192 条 RayQuery。地图重定位会清除未解析区域，CPU 群系降水缓存也采用滑动复用和渐进补齐。
- GPU 双缓冲湿润历史为每条雨线保存当前/前一层表面的深度、水膜和积水量，使遮挡出现或移除后按浸湿、干燥、填充和蒸发时间连续变化。普通方块和树叶只处理几何顶面，小型透雨植物允许各可见面湿润且不遮住下方地面。
- format-3 材质可声明吸水、变暗、水膜保持和蓄水能力。湿表面以水 IOR 1.333 的分层 GGX 薄膜处理；水坑是世界锚定 FBM 场，并与水膜共享湿润颜色端点及连续法线过渡。原生水、玻璃和粒子不会误取方块水膜。
- 原生水面和水坑共享无状态、世界锚定的随机雨滴冲击事件。RT 水花由 CPU 从同一事件定义选择稀疏子集，使用 Fluorite 自有中性水冠/水滴模型并复用粒子 BLAS，不再与原版蓝色水滴重复。
- 密集雨丝在 DLSS-RR 之后、曝光之前进入 HDR pass。D129A 由 compute 每实例计算一次直接光，天空、天体和统一 `Light`/alias/grid 局部光源共同决定颜色与亮度；天体和局部光各最多一条不透明阴影线，并删除夜间固定白色亮度下限。

## 关键裁决与边界

- 否决全图逐帧追踪和纯 CPU 湿润历史：前者 RayQuery 成本过高，后者需要持续读回/上传且不适合逐像素并行更新。最终采用 GPU 分层历史与渐进暴露缓存。
- 水坑不使用真实几何或视差，也不限制固定面积；当前薄层模型优先保证路径一致性和稳定成本，不模拟毫米级水体的真实自由表面位移。
- 涟漪采用阻尼波列的解析近似，没有复制外部 shader 代码，也没有反馈浅水求解，因此不承诺波纹碰撞和相互干涉。
- 水花当前只进入主摄像机路径与可选阴影，不进入反射/GI；雨丝是单次散射近似，不模拟球形水滴高频焦散。M21 不实现雪。
- Debug View 26/27 与视觉校准旋钮保留为 ReSTIR 前 review 候选；它们不是长期配置 ABI。是否固化数值并删除，必须在专项 review 后由用户确认。

## 验收与验证

开发期间依次验收了顶面/植物湿润资格、非方块化干湿边界、水坑可见性与颜色连续性、涟漪和水花共享事件、雨丝方向一致性，以及 D129A 的昼夜/局部光照响应。最终功能视觉验收于 2026-08-14 通过。

自动验证覆盖 Fabric 测试、NeoForge 构建、shader 编译、Java/Slang ABI 与跨 pass 契约；`git diff --check` 无空白错误。M21 的正式 GPU 中位数仍须在 ReSTIR 前性能 review 中测量，不能把静态上限当作实测结论。
