## 起点：ReSTIR 的前一半已经在了

开工前的实测：`lighting.slang` 已有 `Reservoir` 结构和 `risInitial` —— **每着色顶点一次 RIS**，M 个功率加权候选（默认 8，六本地二全局）、alias O(1) 选择、幸存者一条阴影线。`world.rgen.slang:660` 的注释自己写着「single-frame only, no temporal reservoir reuse」。

**缺的是 reuse。** 本里程碑要补的正是时间与空间复用，而复用需要**每像素持久的 reservoir 存储**——这是完全没有的东西。

## D180：先做未压缩版，把「值不值」变成可测量

三个方向性问题请示用户，三个都选了比推荐更贵的档：

| 问题 | 我的推荐 | 用户裁定 |
| --- | --- | --- |
| §8.9「不要提前做时空复用」怎么读 | 依赖满足后可做 | **同上** |
| reservoir 怎么存 | 压缩 ~12 B | **全量** |
| 复用覆盖哪些顶点 | 只主命中 | **全弹射** |

后两项叠加后的内存我在选项里没给全（选项里的 232 MB 是只主命中的），补算后是 1080p/4 弹射约 1 GB。用户的裁定是：

> 你先实现 A 然后 A 要是爆显存了我们再走 C 这样合理一点吧，不实验怎么知道值不值呢

**这与铁律 7 一致**（性能结论只认实测），因此照办。据此产生两条设计约束：

1. **存储格式必须关在一个可替换的边界后面。** `restir.slang` 的 `packReservoir` / `unpackReservoir` / `reservoirSlot` 三个函数 + 一个尺寸常量就是全部接口。改走压缩档时改这四处，不动任何调用点。
2. **存储要先于复用逻辑落地。** 缓冲分配本身就能回答「A 会不会爆显存」，不必等任何复用代码写出来。已验证：用户在深度 4 下分配成功。

### 64 B 而不是 56 B

字段加起来是 56，但 std430 给纯标量成员的结构 stride 就是 56——**不是 16 的倍数**，于是这个「每像素每弹射顶点读一次」的缓冲上每隔一个元素跨 cache line。改成四个 `float4`，多付 14% 换永不跨行。

实际占用 `2 (双缓冲) × 64 B × 复用深度 × 渲染像素`：1080p 下**每层深度 265 MB**，默认弹射数 4 约 1 GB，配置上限 8 约 2 GB。

### 关档与旋钮

`composite.restir-reuse-depth` 默认 **0** = 关：不分配缓冲、push constant 地址为 0、着色回落到单帧 RIS，**与本缓冲存在之前字节级一致**（铁律 8）。旋钮在 Tracing 栏而非诊断栏，因为它改变渲染器行为而不是观测它。

### 这一步消耗了最后一个 push constant 地址

`WorldPushConstants` 现为 14 个地址 + 3 个 uint = 124 → 128 B，**正好是 Vulkan 保证的下限，也正好是 AMD 提供的量**。`RtMaterialLayoutTest` 在还剩 13 个地址时就预言了这个算术并指明了下一步；现在它记录的是「没有余量了，第 15 个地址必须放进 `WorldPush`」——那是 BDA 结构、无此上限，代价是一次间接寻址。

**判据**：新地址是否该放这里，取决于 closest-hit 是否需要它（hit shader 每次命中都读 `pc`、故意从不碰 `WorldPush`）。除此之外现在一律是否。

### 一个自己引入又自己修掉的 bug

`ensureOutput` 在窗口与 upscaler 未变时提前返回。它此前守的一切都只随这两者变化，所以条件里没有 reservoir 深度——**旋钮要等到下一次分辨率变化才生效**。

一个延迟一次 resize 才生效的开关比不存在更糟：它存在的意义就是 A/B，而这样的 A/B 会拿同一棵树跟自己比，然后报告「没差别」。

## D181：接收顶点存世界坐标，因为弹射顶点没有深度

第一版存的是「相机射线深度 + 法线」。**对主命中完全够用，往里走一次弹射就毫无意义**：弹射顶点上没有相机射线，而槽位按 `(像素, 弹射序号)` 寻址、**没有任何重投影**，所以上一帧该像素的第 3 次弹射可以在世界任何地方。

用深度比对等于拿两个不相干的数在比，**碰巧接近就接受** —— 那会是「看起来在工作」的时间复用，实际把上一帧的光照贴到不同几何上。

改存接收顶点的**世界坐标**。腾出的 lane 来自删掉 `wSum` 与 `phat`：

- `phat` **必须**在复用它的那个顶点上重算。把产生它的顶点的值带过来，正是让时间复用出错的经典错误。
- `wSum` 只在 reservoir 填充期存在。
- `W` 才是成品权重，也是着色唯一消费的量。

`unpackReservoir` 对这两个返回 0 而不是看着合理的陈值——读它们而不重算的调用方会立刻得到显然错误的答案，而不是一个似是而非的。

**这条修改发生在任何代码读该格式之前**，是它最便宜的时刻，也正是 D180 把格式关进三个函数的目的。

### 复用判据

两组独立检查，都必须通过：

- **接收端**：位置漂移 ≤ 0.05 格、法线夹角 ≤ 26°。没有重投影，这是复用与「把上一帧光照贴到无关几何上」之间唯一的东西。
- **光源端**（§8.9 硬性要求）：位置、半径（矩形面积）、Radiance **三项全查**。30 bit source key 只标识候选身份，而 entity id 与哈希**都会复用**——只查 key 会静默替换成另一个光源。

**阈值故意放松**：幸存者反正要在当前顶点重算目标函数，所以边缘接受只损失一点精度（且由 S2 的 MIS 权重兜底），边缘拒绝损失的是整个特性。这里错向「接受」更便宜。

`REUSE_M_CAP = 20`（历史上限）沿用文献起点，其定价属 §8.11 测量欠账。
